# Phase 7：GTP 真实回环评测基线

## 1. 目标与边界

本阶段把用户提供的高质量 GTP 曲谱作为本地评测集，建立真实产品闭环：

```text
原始 GP3/GP4/GP5
  → 解析原始谱面
  → 导出 Type-1 多轨 MIDI
  → BandPilot 分轨、识别、修复并生成 SongIR
  → 正式 GP5 导出器
  → 重新解析生成的 GP5
  → 按源轨对齐并比较
```

这里评测的是实际产品边界，不是内存对象之间的模拟比较。语料当前仅用于本地评测；在缺少授权和来源元数据时，不得自动进入知识库、训练集或公开制品。

## 2. 语料盘点

压缩包共 2,335 个条目，其中包含 860 个 `.gp5`、429 个 `.gp3`、298 个 `.gp4` 和 485 个旧版 `.gtp`。当前 PyGuitarPro 不支持 Guitar Pro 2.21 的 `.gtp`，因此基线使用可解析的 GP3/GP4/GP5：

- 支持格式文件：1,587
- 去重后文件：1,557（30 个重复文件）
- 初始成功解析：1,567，失败 20，解析率 98.7%
- 总轨道：6,292，平均每首 4.02 轨
- 原始音符约 458 万个
- 含鼓曲目：769

解析器现已增加 `cp1252 → GB18030 → Latin-1` 回退，可继续减少历史文件编码造成的失败。

## 4. 已定位并修复的问题

- 指法优化遇到单个不可演奏时刻后污染整轨：改为合法片段继续束搜索，仅对局部回退。
- MIDI 鼓通道使用了错误的从 1 开始编号：统一为 `mido` 的 channel 9。
- 同时鼓击全部写入同一虚拟弦导致 GP5 位掩码损坏：每个同时鼓击使用独立虚拟弦。
- 全谱回环丢失轨道、程序号和鼓通道：增加 Type-1 多轨 MIDI 转换。
- 弱鼓/贝司启发式覆盖明确的 GM 程序和轨名：明确证据优先，弱启发式只用于无程序信息轨道。
- 8–14 音键盘和弦超过 GP5 单轨 7 弦上限：拆成两个虚拟声部；大于 14 音明确失败。
- 超长小节休止时值使 GP5 写出失败：分解为可表示时值。
- 非 Latin-1 标题导致 GP5 写出失败：GP5 使用安全降级文本，MusicXML 保留 Unicode。
- 旧技巧指标被大量“双方都无技巧”的音符虚高：改为基于真实技巧事件计数的微平均。

## 5. 当前明确限制

唯一正式样本失败是特殊 6 弦调弦 `[31, 43, 50, 55, 55, 62]`。MIDI 不携带原调弦信息，自动检测选择了标准 8 弦，而 GP5 最多支持 7 弦。当前选择明确报错，避免静默删音或伪造谱面。后续应实现 Top-K 调弦推断、置信度与用户覆盖，必要时通过 sidecar 保留源调弦。

## 6. 下一阶段开发顺序

1. **专业指法模型**：把弦/品、把位移动、开放弦偏好、跨弦、同弦冲突和和弦形状纳入统一代价函数；以曲库真实指法作为排序参考，而不是逐音贪心复刻。
2. **技巧恢复**：先建立可观测证据矩阵，再实现 slide、bend、hammer/pull、palm mute、let ring 等确定性候选；LLM 只做候选重排和解释，不直接改音符事实。
3. **贝司独立优化器**：加入右手交替、换弦、把位跨度、延音与闷音规则，停止复用吉他的全部偏好。
4. **鼓等价评测与映射**：先按鼓件家族评测，再优化 GM 映射，避免指标驱动错误修改。
5. **调弦推断**：Top-K 搜索 + 置信度 + 用户确认/覆盖，保证特殊调弦不丢音。
6. **评测集治理**：补齐哈希、来源、授权、质量评级和 train/validation/test 隔离后，才允许进入自学习闭环。

## 7. 开发规则与质量门禁

- 所有改动必须落在同一真实回环链路上验证，禁止另写一套只为跑分的导出逻辑。
- 音符、节奏、指法、技巧分别设门禁；综合分只能用于排序。
- 不可表示内容必须显式失败或降级并记录，禁止静默删音。
- 知识库只产生可追溯候选；硬约束验证器拥有最终否决权。
- LLM 不负责确定音高、节拍、弦品等事实，不得绕过 SongIR 校验。
- 修复一个样本问题时必须增加最小回归测试，并重新运行全套测试。
- 数据入库必须具备 `source_id`、内容哈希、`license_id`、`permitted_for_training`、质量等级和数据集分区。

## 8. 复现

在 `backend` 目录执行：

```bash
uv run python -m fretpilot.elearning roundtrip \
  --corpus-dir /path/to/extracted/corpus \
  --sample-size 100 \
  --scope full-song \
  --output evaluation_results/gtp_corpus_full_song_baseline.json
```

固定依赖、固定语料哈希和固定抽样规则后，报告可作为后续每个专业演奏优化阶段的回归基线。
